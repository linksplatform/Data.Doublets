The current fork revision 435ad91f44d2fd40c4e4be366163f97333013d65 still needs Conan 2 compatibility metadata changes with Conan 2.34.0. The issue tracker and discussions are disabled, so I am reporting this on the original Conan 2 migration PR.

Reproducer: export `recipes/platform.*/all` at their conandata versions, then run `conan install cpp --build=missing -cc='core:warnings_as_errors=["*"]'` from https://github.com/linksplatform/Data.Doublets/pull/557 with a C++20 profile. The original recipes emit deprecated `cpp_info.names` diagnostics and omit `package_type = "header-library"`, so transitive headers are not propagated. Conan 2 names also require hyphenated aliases in place of the dotted names.

The downstream workaround is `scripts/patch_conan_recipes.py`: classify these packages as header libraries, remove only obsolete `cpp_info.names`/filenames assignments while preserving modern CMake properties, and rename internal Conan aliases consistently. The public CMake targets and namespaces are preserved. Please apply this metadata migration to the upstream recipes and add a test_package that includes the top-level public header with strict Conan warnings enabled. Current external GSL and mio requirements should also be raised to 5.0.1 and cci.20230303.

The separate source defects retain their existing upstream reports: Platform.Data#176/#177 (constexpr/nullable) and Platform.Memory#92/#93 (heap destruction/shrink). Current third-party GoogleTest/Benchmark recipes now replace the previous downstream source compatibility workarounds; those patches have been deleted in PR #557.
