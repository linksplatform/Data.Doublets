The shared C# documentation/PDF scripts fail on current Ubuntu/.NET 8 projects. Evidence: https://github.com/linksplatform/Data.Doublets/actions/runs/40767419162 and https://github.com/linksplatform/Data.Doublets/pull/526 (full logs preserved under dev/log/issues/524/pulls/526).

Reproduction: run publish-csharp-docs.sh on ubuntu-latest for a net8.0 project. `apt-get install nuget` fails with "Package 'nuget' has no installation candidate". The script also pins an old Mono/DocFX 2.51 toolchain and a netstandard2 metadata target. Separately, generate-csharp-pdf.sh requests obsolete `python-pygments` ("Unable to locate package python-pygments") and its formatter uses Python 2-era encoding conventions. A generated PDF is not reliably incorporated in the published site.

Workaround used in Data.Doublets PR #526: pinned .NET 8.0.427, local .NET tool DocFX 2.81.0, strict `--warningsAsErrors`, net8.0 metadata, Python 3/fpdf2 with Unicode DejaVu font and bounded source rendering, PDF generated before DocFX resource copying. Validate all local HTML links and the PDF signature before uploading/deploying the artifact. This produces 85 checked HTML pages and a source PDF without warnings. DocFX 2.81.0 also contains the namespace-href fix https://github.com/dotnet/docfx/pull/11163 .

Suggested fix: replace unsupported apt/Mono/Python 2 installs with pinned maintained tools; build docs and PDF on PRs without secrets; publish only those validated artifacts from a main writer; keep credentials in a Git helper, never URLs; preserve other language documentation and propagate all build/deploy failures. Test Unicode sources and missing PDF resources in automated checks.
