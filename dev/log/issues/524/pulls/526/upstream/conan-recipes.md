Observed with Conan 2.33.0 while repairing https://github.com/linksplatform/Data.Doublets/issues/524 (PR https://github.com/linksplatform/Data.Doublets/pull/526), using linksplatform/conan-center-index revision 435ad91f44d2fd40c4e4be366163f97333013d65.

The `recipes/platform.*/all/conanfile.py` recipes represent header-only libraries but omit `package_type = "header-library"`. Conan 2 therefore does not propagate the intended transitive header requirements through the dependency graph. Current package_info methods also retain deprecated Conan 1 `self.cpp_info.names[...]` assignments.

Reproduce in Data.Doublets: install Conan 2.33.0, detect a C++20 Release profile, export the pinned platform recipes (as cpp/install-local-conan-dependencies.sh does), run `conan install cpp --output-folder=cpp/build --build=missing`, then configure CMake with its generated conan_toolchain.cmake and build tests. The unpatched recipes lose transitive include paths, producing missing `Platform.Hashing.h` / `gsl/gsl` includes. Full diagnostic logs and pinned recipes are preserved in PR #526 under dev/log/issues/524/pulls/526.

Workaround applied downstream: add `package_type = "header-library"` to each platform recipe, remove obsolete `cpp_info.names` settings while retaining `cmake_file_name`/`cmake_target_name` properties, and explicitly require/link Microsoft.GSL in the consumer. Export platform.hashing at its recipe-supported version 0.5.6 rather than passing an incompatible version.

Suggested fix: classify these header-only recipes explicitly, declare requirements with appropriate transitive_headers/transitive_libs traits where necessary, remove deprecated generators' names metadata, and add a Conan 2 test_package that consumes only the top-level target, compiles an umbrella header and executes a small program. Test both GCC and Clang. The relevant Conan model is documented at https://docs.conan.io/2/reference/conanfile/attributes.html#package-type and https://docs.conan.io/2/reference/conanfile/methods/requirements.html .
